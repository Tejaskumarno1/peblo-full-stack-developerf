# Server changes that still need a database test

Commits `94ced39` and `c3f01da` (team authorization fixes) compile (`npm run build:server`) but have **never been run against a database**. Run these against a **local** Postgres named `peblo_test` (never `server/.env`, which points at production). `scripts/smoke-test.mjs` has one new check (sole-owner account deletion) that has not been run either.

1. **Sole owner cannot delete the account.** Create a user, make an organization, call `POST /auth/delete-account` and `/auth/schedule-deletion`: expect 409. Add a second active owner: expect 200. Set `deletion_requested_at` to 31 days ago for a sole owner and run `purgeScheduledDeletions`: the user must survive.
2. **Team note manage rights.** Team with A (author), B (member), C (lead). B gets 403 `owner_only` on DELETE, restore, archive, move, `PATCH {isArchived}` and `?permanent=1`. A and C succeed. Personal and Office behaviour is unchanged. Check the client toast text for `owner_only` and `no_access`.
3. **Join link.** `lookup` returns `ready`. Accept with `max_uses=1` from two concurrent requests: exactly one succeeds. Make `space_members` fail: `uses` is not burned. Set the org to `read_only`: `revoked`.
4. **Invite accept.** Accept twice at once: one 200, one 409 `state:'used'`. Revoke then accept: 409. Put a closed space and another org's space in `space_ids`: no `space_members` rows for them.
5. **`PUT /spaces/:id/members/:userId`.** Demote the only lead: 409. Make an org guest a lead: 400. Demote one of two leads: 200.
6. **Guest `GET /orgs/:id/members`.** Only name, avatar, role and status; only people sharing a space with the guest plus the guest; `invites` is `[]`. A non-guest gets the full list. Confirm the client does not break on missing `email` and `spaces`.
7. **Live edit after removal.** Remove a member who authored a team note: `/collab/ticket` returns 404 and the open socket closes. An author who is still a member keeps live edit in Team, Office and Personal.
8. **`spaceMembers()`.** Assign a task to an expired guest, a paused member and a member of a closed org: expect the "not in this space" 400.

Known gaps left on purpose: an invite to a `read_only` org still reads as `ready`; the guest member list does not exclude people who share only a closed space; check that a last owner can actually leave (the deletion message tells them to).

## Team lifecycle (branch feat-team, never run against a database)
Migration `051_org_purge_after.sql` (adds `organizations.purge_after`; 047-049 were already taken). Run against a **local** Postgres `peblo_test` only. `scripts/smoke-test.mjs` has a new block "Team lifecycle" at the end (about 45 checks, unrun) that covers most of the steps below.

9. **Note handover (R8).** Org with owner O, members F and G; F writes a team note (with a tag) and a private Office note. `POST /workspaces/orgs/:org/members/:F/handover-notes {toUserId:O}`: 200 `moved` counts both only when O is a lead/member of those spaces (otherwise `moved:0`, `skipped` lists them). Check `notes.user_id = O`, `updated_at` unchanged, the Office note still `office_everyone IS NULL` and now readable by O only, the note's tag now belongs to O (`tags.user_id`) and `note_tags` points to it, `note_access` rows of O for these notes are gone, `audit_log` has `member.notes_handover`, O got a notification. A plain member gets 403; `toUserId` of a non-member, a guest, a paused member or an expired guest gets 400 `not_member`. Remove F first (`DELETE members/:F`), then hand over: still works, and `GET /orgs/:org/orphaned-notes` lists F before and not after.
10. **Remove from one team (R6).** `DELETE /workspaces/spaces/:space/members/:user`: a plain member 403; a lead 200; an owner/admin who is not in the team 200; the only lead 409 `last_lead`; the person stays in `org_members`; their open tasks in that team have `assignee_id NULL`; audit `space.member_removed`; they get a notification; their live socket for that team's notes closes (see test 7).
11. **Reopen (R16).** Lead closes a team, `GET /orgs/:org/closed-spaces` lists it (for the lead and for owner/admin, not for others), `POST /spaces/:id/reopen`: plain member 403, lead 200, again 409; `spaces.closed_at` is NULL and the team is back in `GET /workspaces`; reopening in a `read_only` or closed org is refused.
12. **Delete organization (R16).** `DELETE /workspaces/orgs/:org {confirmName}`: wrong name 400 `name_mismatch`; non-owner 403; other active members 409 `has_members`; sole owner 200: `status='closed'`, `closed_at` set, `purge_after` about 30 days ahead, pending invites and join links revoked, rows in notes/spaces/todos still there, the org is gone from `GET /workspaces`, audit `org.deleted`, remaining paused/guest members notified. Calling it again 404.
13. **Seat limit (R15).** Set `policy.seatLimit` to the number of active non-guest members: `POST invites` 409 `{code:'seat_limit'}` with the limit in the text; raise by 1: one invite works, the next fails (pending invites count); a guest invite is never blocked; re-inviting the same email does not double count. Accept an invite or use a join link when the org is full: 409 `seat_limit`, `state:'seat_limit'`, the invite stays unaccepted and `org_join_links.uses` is unchanged. Two concurrent accepts for the last seat: exactly one succeeds. `PATCH member {role:'member'}` on a guest, or `{status:'active'}` on a paused member, in a full org: 409.
14. **Guest expiry (R15).** `PATCH member {guestUntil}` for a guest: past date 400, more than a year 400, non-guest 400, valid 200 and `guest_until` updated; an expired guest regains access after the extension (`GET /workspaces` lists the org again). Changing a guest to member clears `guest_until`; changing a member to guest sets 30 days.
15. **Team notes payload (R26, R27, R33).** `GET /notes` and `GET /notes/:id` with `X-Peblo-Space` of a Team: each note has `team:true`, `owner{id,name}`, `level`, `access`, `canManage`, `lastEditedBy`. Author: `owner`/true; another writer: `edit`/false (`view` when `meta.teamShare.level='view'` or the person is a viewer); a lead: `canManage` true. Offices keep the old fields (no `team`). In the app: open a "can view" team note as a non-author: View only badge, no typing, no Archive/Pin/Move/Duplicate/Share/Trash in the menu.

Known gaps: no purge job for `purge_after` and no way to restore a deleted organization; files and images uploaded by a departed author keep their old owner after a note handover; `lastEditedBy` comes from the version history (who overwrote the previous text), so it can lag; the trial is still not enforced; bulk actions on the notes page do not check manage rights per note.
